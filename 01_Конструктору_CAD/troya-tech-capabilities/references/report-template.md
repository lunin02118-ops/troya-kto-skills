# Шаблон отчёта о технологичности

```markdown
# Технологичность: <обозначение> <наименование>

Основание: модель <файл> (замеры через MCP / по чертежу / по ТЗ) · дата <ДД.ММ.ГГГГ>

## Итог
<OK / УСЛОВНО / НЕЛЬЗЯ своими силами> — одной фразой почему.

## Маршрут
| Поз. | Деталь | Материал, профиль | Операции (станок) | Вердикт |
|---|---|---|---|---|
| 1 | Стойка | Труба 32×1,2 Ст3 | Труборез K0-65 → гибка CNC-35/ED R70 ×2 → сварка MIG → порошковая покраска | OK |
| 2 | Поперечина | Профиль 40×20×1,5 | Труборез K0-65 → гибка R100 | УСЛОВНО: оснастки R100 для 40×20 нет |

## Замечания к КД
| № | Поз. | Что не так | Предел / правило (код, достоверность) | Предложение |
|---|---|---|---|---|
| 1 | 2 | R100 для 40×20 «плашмя» | G-01 (лист цеха): есть R90 и R120 | Заменить на R90 |

## Запросить (пробелы в данных)
- <станок>: <что узнать> — <у кого>

## Допущения
- Пределы со статусом «Только ОС» или «Общее правило» — ориентир, требуют подтверждения технологом.
```

Правила оформления:
- В отчёте — только цифры с источником; каждый предел со статусом ниже «КП/каталог» помечай.
- Вердикт по изделию равен худшему вердикту его деталей.
- Предложение по КД должно быть конкретным: новое значение, а не «пересмотреть».
