# CAD Assembly Structure Organizer & Folder Architecture System

## 📌 Назначение
Организация чистой, стандартизированной файловой архитектуры конструкторских заявок и изделий по утвержденному эталону предприятия (**`<WORK>\03_Проекты\85_Т`**), изоляция покупного крепежа в отдельную папку `Стандартные изделия и фурнитура\`, сохранение ссылок через preflight, резервную копию, fail-closed replacement и проверку зависимостей/компонентов. Процессные действия выполняются только в явно выделенной и принадлежащей сессии; глобальная остановка процессов запрещена.

---

> сборки и CAD-ссылках действуют.

## 🔩 4. СТРОГАЯ ИЗОЛЯЦИЯ КРЕПЕЖА И СТАНДАРТНЫХ ИЗДЕЛИЙ

1. **Покупной крепеж и фурнитура**:
   - Винты, гайки, шайбы, заклепки, саморезы, опоры регулируемые, заглушки труб, комплекты клин-петля, замки, стяжки.
   - Хранятся **ТОЛЬКО** в папке `Стандартные изделия и фурнитура\`.
   - **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО** присваивать покупным изделиям чертежные децимальные шифры (например, `СУAt-05.00.003 Винт` — ❌ ОШИБКА).
   - Имена файлов — строго по ГОСТ/DIN/ISO (`Винт ISO 7380-1 M8x16.SLDPRT`, `Саморез DIN 968 4.2x16.SLDPRT`).
2. **Крепежные элементы собственного изготовления**:
   - Уголки монтажные, кронштейны, пластины, фланцы, изготавливаемые на лазере/гибочнике завода TROYA.
   - **ОБЯЗАНЫ** иметь децимальный шифр: `СУAt-05.00.002 Уголок 20х20.SLDPRT`.
   - Размещаются в `Стандартные изделия и фурнитура\` либо в корне/папке узла.

## 🔗 5. ПРИНЦИП ZERO-BROKEN-LINKS (100% ЦЕЛОСТНОСТЬ ССЫЛОК)

1. При любых перемещениях файлов в новую структуру путей ссылки в сборках (`.SLDASM`) и чертежах (`.SLDDRW`) обновляются:
   - Через SolidWorks Document Manager API или COM API `ReplaceReferencedDocument`.
   - Либо через скрипты пересборки структуры с `AddComponent5` и расстановкой `Transform2`.
2. После реорганизации обязателен аудит открытия главной сборки:
   - Все компоненты должны быть `Suppressed == False`.
   - Все компоненты должны быть `Resolved` (Zero Missing Files).

Реализация сначала фиксирует baseline через `GetDependencies2(True, False, False)` и состояния компонентов. `ReplaceReferencedDocument` вызывается только для реально сохранённых old-путей; после замены проверяются пары name/path, отсутствующие зависимости и только новые изменения suppression state. Предсуществующее состояние компонента сохраняется как baseline. При ошибке восстанавливаются bytes сборок и перемещённые пути из уникального backup manifest.

3. Раскладка готового изделия по папкам подсборок (отработано на столах Офис Восток, 09.11.2026):
   - файлы закрыты, снят полный снимок плоской папки со сверкой SHA-256;
   - карта «старый полный путь → новый» охватывает все файлы; если одно изделие заимствует детали другого, карта общая на оба;
   - для каждого файла читать `GetDocumentDependencies2` дважды: без поиска (что записано) и с поиском (где файл найден); записанный путь заменяется новым путём найденного файла;
   - `ReplaceReferencedDocument` применять к сборкам, чертежам и деталям с контекстными ссылками; ссылки на библиотеку и на файлы вне карты не менять;
   - приёмка: ссылки без поиска и с поиском ведут в новое дерево, главные сборки открываются без погашенных и ненайденных компонентов, масса та же, чертежи без висячих размеров, текст PDF всех чертежей совпадает с выгрузкой до переноса.

## 🧹 6. ПРИНУДИТЕЛЬНОЕ УНИЧТОЖЕНИЕ ЗОМБИ-ПРОЦЕССОВ

Временные lock-файлы `~$*.*` и `.tmp` только перечисляются для ручного решения. Обменные форматы STEP/IGES/Parasolid и резервные/старые версии не удаляются автоматически. Глобальная зачистка процессов и удаление файлов блокировок запрещены.
