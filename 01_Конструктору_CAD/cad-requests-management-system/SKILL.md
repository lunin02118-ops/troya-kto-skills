Инженерная система Antigravity для организации, аудита и поддержания порядка в сетевом хранилище заявок конструкторского отдела:

## 🛑 1. ГЛАВНЫЙ РЕГЛАМЕНТ И СТРУКТУРА ПАПОК ЗАЯВКИ

Вся работа ведется в строгом соответствии с корпоративным документом **«Инструкция по папкам конструкторской заявки»** (Ред. 3 от 15.10.2026 по ТЗ-03 ред. 8 и ТЗ-04; копия — [references/Инструкция_Папка_заказа.md](references/Инструкция_Папка_заказа.md)) и эталонным шаблоном **`_Шаблон_заказа`**.


## ⛔ 2. ЖЕЛЕЗНЫЕ ПРАВИЛА ЧИСТОТЫ ЗАЯВКИ (ZERO-DUPLICATION & ZERO-EXTRACTION)

### 🚫 Правило 1. СЛУЖЕБНАЯ ЗАПИСКА — СТРОГО В КОРНЕ (ДУБЛИРОВАНИЕ ЗАПРЕЩЕНО)
- Служебная записка (СЗ) размещается **ТОЛЬКО ОДИН РАЗ — В КОРНЕ ПАПКИ ЗАКАЗА** (`СЗ №...docx` или `.pdf`).
- **СТРОЖАЙШЕ ЗАПРЕЩЕНО копировать/дублировать СЗ** в `01_Исходные данные\Документы\` или любые другие подпапки.
- **СТРОЖАЙШЕ ЗАПРЕЩЕНО создавать текстовые дубликаты СЗ** (`.md`, `.txt`), если уже есть официальный файл СЗ. В корне должен быть чистый комплект без задвоения.

### 🚫 Правило 2. ФОТО И ВИДЕО ИЗ СЗ НЕ ИЗВЛЕКАТЬ
- **СТРОЖАЙШЕ ЗАПРЕЩЕНО извлекать картинки, рендеры, таблицы или эскизы из файла СЗ** (из `.docx`, `.doc`, `.pdf`) и раскладывать их в `01_Исходные данные\Фото и видео\` или `03_Корпус\05_Визуализация\`.
- Файл СЗ является целостным документом. Конструктор изучает изделие, габариты и визуализацию прямо в документе СЗ.
- Папка `01_Исходные данные\Фото и видео\` предназначена **ИСКЛЮЧИТЕЛЬНО для самостоятельных медиафайлов**, присланных заказчиком или менеджером отдельно (фото замеров с объекта, видео осмотра помещений, файлы из WhatsApp). Если таких файлов нет — папка **остается пустой**!

### 🚫 Правило 3. НАЗНАЧЕНИЕ ПАПКИ `01_Исходные данные\Документы\`
- Предназначена **ТОЛЬКО для сторонней документации заказчика** (ТЗ, сметы, локальные сметы (ЛС), договоры, накладные, акты, сертификаты от клиента).
- Служебная записка конструктора и проектного менеджера сюда **НЕ кладется**. Если документов от заказчика нет — папка остается пустой.

### 🚫 Правило 4. НАЗНАЧЕНИЕ ПАПКИ `03_Корпус\05_Визуализация\`
- Сюда помещаются **только собственные визуализации корпусного конструктора** (проекты D5 Render, рендеры Базиса и bCAD, эскизы согласования с клиентом). Дублировать сюда картинки из СЗ или из `01_Исходные данные\Фото и видео` запрещено.

## 🔤 3. СТАНДАРТ ИМЕНОВАНИЯ ПАПОК ЗАЯВОК

* **Формула:** `<номер>_<код>_<объект>_<город>`
* **Ограничение длины:** имя папки — **не более 40 знаков**.
* **Разделитель блоков:** строго нижнее подчеркивание `_`. Внутри блоков пробелы разрешены.

| Часть | Правило | Примеры |
|---|---|---|
| `<номер>` | Номер заказа; под-номер через дефис | `85-1`, `207-1`, `71`, `222` |
| `<код>` | Источник заказа: `Т`, `Ал` (алматинское), `Аст` (астанинское), `М` (Москва); ВЭД убран 15.10.2026 | `Т`, `Ал`, `Аст`, `М` |
| `<объект>` | Коротко наименование объекта/клиента без спецсимволов (`№ « » , . ! + #`) | `Гостиница Центр`, `Офис Север`, `Школа 10` |
| `<город>` | Город без «г.» или «г» | `Астана`, `Алматы`, `Павлодар` |

**Примеры правильных имен:**
- `222_Аст_Гостиница Центр_Астана`
- `175_Аст_Офис Север_Астана`
- `85-1_Т_Центр услуг_Актау`
- `207-1_Аст_Офис Юг_Астана`
- `56_Ал_Шоурум_Алматы`

## 🛠️ 4. ИНСТРУМЕНТЫ АВТОМАТИЗАЦИИ СКИЛЛА (`scripts/`)

### 1. `create_request.py` — Создание новой заявки
Развертывание заявки по эталонному шаблону `_Шаблон_заказа`:
```bash
python scripts/create_request.py --execute --number "222" --code "Аст" --object "Гостиница Центр" --city "Астана" --sz-file "C:\path\to\СЗ.docx"
```
*Автоматически копирует эталонную структуру из `_Шаблон_заказа`, размещает СЗ строго в корне папки, не дублирует файлы в `Документы` и не извлекает медиа из СЗ.*

### 2. `audit_requests.py` — Инженерный аудит хранилища
Сканирование и выявление нарушений стандарта Ред. 2 (дубли СЗ в `Документы`, мусор, некорректные имена):
```bash
python scripts/audit_requests.py
```

### 3. `clean_junk.py` — Зачистка мусора и временных файлов
Поиск и карантин `Thumbs.db`, `Desktop.ini`, `~$*.docx`, `~$*.xlsx`, `*.tmp`:
```bash
python scripts/clean_junk.py --execute
```

### 4. Нормализация папок заказа
`normalize_requests.py` убран в архив пакета 25.10.2026: он переносил файлы в заготовку `_Шаблон_изделия` вместо папки изделия.
Раскладывать файлы по папкам заказа — навыком `kto-folders` (`sort_plan.py` → проверка плана → `apply_plan.py`).
